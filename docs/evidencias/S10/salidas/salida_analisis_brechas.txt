  JUSTIFICACIÓN ARQUITECTÓNICA DE LA SECUENCIA DE TRANSICIÓN:
  1. No es viable ejecutar analítica ni scoring v2 antes de estabilizar el Maestro de Clientes (PT-01),
     de lo contrario los modelos de Machine Learning entrenarán con datos contradictorios o duplicados.
  2. No se puede desmantelar el Shadow IT (hojas de cálculo de cobranzas HC-01 y scoring HC-04)
     antes de desplegar la plataforma CRM/BPM (PT-04) y el nuevo motor API (PT-06), pues el negocio quedaría
     sin capacidad operativa para gestionar su cartera morosa.
  3. El API Gateway (PT-07) es prerrequisito de integración para la firma digital (PT-03), el CRM de cobranzas
     (PT-04) y el sistema de reclamos (PT-05), garantizando seguridad perimetral y trazabilidad de transacciones.
